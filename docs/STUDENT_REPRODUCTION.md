기록일: 2026-10-23(KST) · 상태: **검증 중**

이 문서는 자동화 도구를 사용한 로컬 실행 관찰과 학생 문서입니다. 서버 AI가 새 환경에서 실행했다는 증거가 아니며, 실제 운영 인증이나 v1.0 인증을 주장하지 않습니다. 사용자가 새 PowerShell 창에서 직접 대조하는 확인과 공식 제출·판정은 기다림(UNV)입니다.

## 2. 다른 환경에서 같은 커밋을 받는 절차

아래는 프로젝트를 담을 상위 폴더의 새 PowerShell에서 진행합니다. 기존 프로젝트 안에서 실행하지 않습니다. `$targetCommit`에는 최종 보고 또는 과제 화면에 제출할 실제 40자리 값을 입력합니다. 폴더가 이미 있다면 새 이름을 고르고 기존 내용을 지우지 않습니다.

```powershell
$targetCommit = Read-Host '제출할 40자리 커밋'
if ($targetCommit -notmatch '^[0-9a-fA-F]{40}$') { throw '40자리 커밋을 확인하세요.' }
$cloneDirectory = Join-Path (Get-Location).Path 'Sentinel-Defense-Battle-final-20261023'
if (Test-Path -LiteralPath $cloneDirectory) { throw '기존 폴더를 덮어쓰지 않습니다.' }
git clone --branch main https://github.com/gyeonggumun/Sentinel-Defense-Battle.git $cloneDirectory
if ($LASTEXITCODE -ne 0) { throw '복제 실패' }
Set-Location -LiteralPath $cloneDirectory
git switch --detach $targetCommit
if ($LASTEXITCODE -ne 0) { throw '대상 커밋 확인 실패' }
git rev-parse HEAD
git status --short
```

`HEAD`가 입력한 커밋과 같고 작업 트리가 깨끗해야 합니다. `main`이라는 이름만으로 나중에 이동한 커밋을 같은 결과로 취급하지 않습니다. 인증·설정 파일을 원래 폴더에서 복사하지 않습니다.

실제 실행은 이 새 체크아웃의 최상위에서 합니다. 21단계 설명서의 사용자 PC 절대경로는 당시 작업 위치의 기록이며 실행 코드의 의존성이 아닙니다. 다른 환경에서는 새로 복제한 실제 폴더로 이동한 뒤 상대경로 명령을 사용합니다. 서버·실행 도구는 자신의 파일 위치를 기준으로 동작합니다.

## 4. 같은 최종 커밋의 13~21단계 결과

표의 확인 시각은 **2026-10-23 22시대(KST)**입니다. 초 단위 시각과 실제 40자리 커밋은 프로젝트 밖 `final-run.json`, `browser-observations.json`, `final-http.json`에 함께 남깁니다. 정적 소스 확인·DOM 모의 검사·실제 브라우저 관찰을 분리하며, 과거 단계의 통과 판정을 가져오지 않습니다.

| 단계 | 확인 기능 | 최종 체크아웃의 관찰 결과 | 근거·미확인 원인 |
|---|---|---|---|
| 13 | 세 메뉴·계정·기기·세션 표시 | 실제 브라우저의 「보호 현황」「업무 앱」「보안 기록」과 연결 실패 표시 확인. 실제 계정은 **연결 없음** | 브라우저 관찰 기록, `/api/me`의 `ENGINE_NOT_CONNECTED`. 사용자·기기·세션 실제 정보는 UNV |

DOM 모의 검사는 네트워크 요청을 허용하지 않는 테스트 대역을 사용했습니다. 과거 커밋 간 차이를 검사하던 항목은 제외하고, **최종 체크아웃의 함수 동작 55개를 한 번에 실행한 결과**입니다. 각 검사 파일의 해시와 검사 실행 시각도 `final-run.json`에 기록합니다. 테스트 파일은 프로젝트 밖 증거 폴더에 보존하며 앱 의존성이나 제출 원문에 추가하지 않았습니다. 이 테스트 도구 자체를 GitHub에서 재취득하는 절차는 제공하지 않으므로 다른 PC의 모의 검사 재현은 별도 준비가 필요합니다.

이번 재현에서 `npm run demo`는 실행하지 않았습니다. 예제 자료의 성공을 실제 연결 성공으로 합산하지 않습니다. 실제 브라우저 검증도 계정·XDR·AI·집행·OSV의 외부 운영 연결 검증과 다릅니다.

## 5. 증거 목록과 실패 시 재검증

| 프로젝트 밖 증거 파일 | 내용 |
|---|---|
| `original-before.json`, `original-after.json` | 원본 커밋·Git 상태·앞 단계 파일 7개 해시·확인 시각 |
| `final-run.json` | 최종 40자리 커밋·환경·모의 검사 수·검사 파일 해시·시각 |
| `final-mocks.tap` | 같은 최종 체크아웃을 대상으로 한 모의 검사 55개 결과 |
| `final-http.json` | 로컬 API의 공개 가능한 상태·오류 코드만 기록. 자격·응답 원문 없음 |
| `browser-observations.json` | 실제 화면에서 확인한 메뉴·표시 문구·시각·최종 커밋 |

| `source-history.bundle`, `backup-restore.json` | 소스 Git 백업·검증·별도 복원 체크아웃의 커밋 확인 |

증거 파일은 커밋된 앱 데이터가 아니며, 서버 AI가 자동으로 읽었다고 주장하지 않습니다. 과제 원문 검토에는 이 문서의 요약을 사용하고, 별도 증거 전달이 필요한 경우 사용자가 대상·내용을 확인합니다. 원문 전달 도구가 프로젝트 밖 증거까지 자동으로 묶는다고 가정하지 않습니다.

오류로 코드나 실행 계약을 바꾸면 새 커밋을 기록하고, **새 최종 커밋에서 위 전체 절차를 다시 수행**합니다. 서로 다른 커밋의 일부 성공을 더해 전체 완료로 표시하지 않습니다. 문서 커밋 이후 마지막 검증이 실패하면 해당 범위는 UNV로 남기고 릴리스를 확정하지 않습니다.

| AI/SDP 자격·인증서·토큰·호스트 보관함 | 프로젝트·증거·제출 원문 밖의 담당자 관리 영역 | 무작정 복사·출력하지 않음. 승인된 계정 재연결·재발급 절차 사용. 이번 작업에서 이전하지 않음 |
| 실제 조치 접수·결과 저장소 | 집행기·운영자 정책에 따라 별도 보존 필요 | 현재 실집행 연결 미완료. Git 복원으로 조치 효과를 되돌릴 수 없음. 운영 복원은 UNV |

이번에는 커밋된 소스의 bundle 생성·검증·새 폴더 복원과 커밋 일치만 확인합니다. 다른 PC에서 실행할 수 있도록 만든 백업이지만 다른 PC의 런타임 실행까지 확인한 것은 아닙니다.

```powershell
# 대상 저장소 최상위에서, 프로젝트 밖의 새 백업 경로를 입력합니다.
$backupFile = Read-Host '프로젝트 밖의 새 bundle 파일 경로'
if (Test-Path -LiteralPath $backupFile) { throw '기존 백업을 덮어쓰지 않습니다.' }
git bundle create $backupFile --all
if ($LASTEXITCODE -ne 0) { throw '백업 실패' }
git bundle verify $backupFile
# 복원은 기존 작업 폴더를 덮지 않는 새 경로에서 수행합니다.
$restoreDirectory = Read-Host '아직 없는 복원 폴더 경로'
if (Test-Path -LiteralPath $restoreDirectory) { throw '기존 폴더를 덮어쓰지 않습니다.' }
git clone $backupFile $restoreDirectory
```

## 7. 버전·지원 범위와 제출

[학생 릴리스 기록](STUDENT_RELEASE.md)에 따라 현재는 **검증 중**입니다. 지원 확인 범위는 같은 PC의 새 폴더, 위 런타임, 기본 미연결 화면, 로컬 설치·실행·종료·재실행, 해당 최종 소스의 모의 표시 계약입니다. Node.js 24.19.0·다른 OS/브라우저·실제 SDP/XDR/AI·실집행·실제 OSV·원격 데이터 복원·공식 접수는 기다림(UNV)입니다.

21·22단계 제출은 [21단계 설명서 9절](STUDENT_RUNBOOK.md#9-2122단계-커밋과-제출-순서)을 따릅니다. 저장소 URL과 실제 최종 40자리 커밋을 과제 화면에 직접 입력합니다. 워크벤치 「포털 제출 준비」의 지원 범위는 13~20단계입니다. 비공개 원문 도구는 과제 화면의 「비공개 저장소 원문 준비 방법」에 있는 정확한 명령·실제 도구 경로를 확인한 뒤 사용합니다. 현재 도구 파일·경로가 제공되지 않아 명령을 만들어 실행하지 않습니다. 실제 제출·원문 전송·공식 판정은 이번 자동화에서 수행하지 않습니다.

22단계 원문 검토 수료와 실제 운영 인증은 다릅니다. 실제 집행 등 미완료 항목을 전체 완료 조건에서 빼거나 v1.0 자동 인증으로 해석하지 않습니다.
