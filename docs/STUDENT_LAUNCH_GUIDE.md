# 케셰브 시작·실행 안내 (학생용)

이 안내는 13~22단계에서 만드는 보안 Agent 앱 **케셰브**를 내 PC에서 처음 실행하고, 종료하고, 다시 실행하는 방법을 설명합니다.

- **케셰브**: 내 PC의 워크벤치 프로젝트 폴더 안에서 실행하는 보안 Agent 앱입니다. 13~22단계 동안 이 프로젝트 하나를 계속 고쳐 나갑니다. ALEPH 포털과 안내에서는 이 앱이 케셰브 또는 내가 정한 앱 이름으로 표시됩니다. 포털에서 이름을 바꿔도 이미 받은 프로젝트 파일과 실행 중인 앱 제목은 자동으로 바뀌지 않습니다.
- **CLCO**: AI 요청을 중계하는 서버(AI 게이트)입니다. 학생 프로젝트를 저장하는 곳이 아닙니다.
- **ALEPH**: 단계 안내를 읽고, 커밋한 코드를 제출하고, 판정 결과를 확인하는 곳입니다.

> 13단계 시작 틀은 ALEPH 4차 과제 화면의 「13단계 시작 틀 받기」에서만 받습니다. 다른 곳에서 받은 파일은 쓰지 않습니다.

## 1. 어느 폴더에서 시작하나요

| 내 상황 | 할 일 |
|---|---|
| 1~12단계 프로젝트가 있습니다 | 그 워크벤치 프로젝트 폴더에 시작 틀을 **추가**합니다. 기존 파일과 이전 기록은 지우거나 덮어쓰지 않습니다. |
| 3차를 마치지 못했거나 프로젝트가 없습니다 | 워크벤치에서 **새 프로젝트**를 만들고, 시작 틀로 13단계부터 시작합니다. |

- 어느 경우든 시작한 프로젝트 하나로 22단계까지 진행합니다. 단계마다 새 폴더를 만들지 않습니다.
- 개인 연습 폴더나 다른 사람의 폴더를 쓰지 않습니다.
- 이 GitHub 저장소는 최상위에 `package.json`과 `src/server.mjs`가 있으므로, 이 폴더가 **앱 폴더이자 Git 최상위 폴더**입니다. `on-client` 하위 폴더는 없습니다.
- 다른 워크벤치 프로젝트에 시작 틀을 추가한 경우에는 `package.json`이 있는 앱 폴더에서 실행하고, 커밋은 해당 프로젝트의 Git 최상위에서 합니다.

## 2. 처음 실행하기

준비할 것: Windows PowerShell과 Node.js. `package.json`은 **24.19.0**을 기준 버전으로 선언합니다. 다른 버전이더라도 실행 도구가 Node.js 22~24를 허용할 수 있지만, 같은 환경을 재현하려면 24.19.0을 사용하세요.

1. 파일 탐색기에서 `package.json`이 있는 앱 폴더를 엽니다.
2. 주소 표시줄에 `powershell`을 입력하고 Enter를 누릅니다. 그 폴더에서 PowerShell 창이 열립니다.
3. 다음 명령을 차례로 실행합니다.

```powershell
node --version
npm run check
npm start
```

4. 터미널에 `케셰브 연결 확인: http://127.0.0.1:5189`가 보이면 로컬 서버가 시작된 것입니다. 이 시작 신호는 SDP·XDR·AI의 실제 연결 성공을 뜻하지 않습니다.
5. 브라우저에서 <http://127.0.0.1:5189/>를 엽니다. 학생 화면의 자료 출처와 `연결 없음`, `확인 불가`, `예시 자료(demo)` 상태를 구분해서 확인합니다.

`npm run check`는 `student/extension.mjs` 문법 검사이며 화면 전체나 외부 연결 검사는 아닙니다. 서버를 종료하려면 실행한 PowerShell에서 `Ctrl+C`를 누릅니다.

> **OneDrive·바로가기 경로에서 `ReparsePoint` 오류가 날 때**
> `tools/start-alekov.ps1`은 앱 폴더·`src/server.mjs`·`package.json`이 링크(ReparsePoint)로 표시되면 실행을 거부합니다. 프로젝트를 복사하거나 보안 설정을 바꾸지 말고 위의 `npm start`를 사용합니다. 이 명령은 같은 `src/server.mjs`를 실행하지만 시작 도구의 사전 Node.js·포트 검사는 하지 않습니다.

## 3. 종료하기와 다시 실행하기

- **종료**: 앱을 실행한 PowerShell 창에서 `Ctrl+C`를 누릅니다. 브라우저에서 주소가 더 이상 열리지 않으면 종료된 것입니다.
- **다시 실행**: 같은 앱 폴더에서 `npm start`를 다시 실행하고 브라우저를 새로고침합니다. 두 서버를 같은 포트에서 동시에 실행하지 않습니다.
- **다른 포트 사용**: 새 PowerShell에서 `$env:ON_PORT='5190'`을 설정한 뒤 `npm start`를 실행하고 `http://127.0.0.1:5190/`을 엽니다. 기본 포트로 돌아갈 때는 새 PowerShell을 열거나 `Remove-Item Env:ON_PORT -ErrorAction SilentlyContinue`를 실행합니다.
- 제공 시작 도구의 `-Background` 옵션은 `ReparsePoint`가 아닌 일반 경로에서만 사용할 수 있습니다. 실행 창을 직접 관리할 수 있는 경우 기본 `npm start` 방법을 권장합니다.

## 4. 문제가 생겼을 때

아래 경우 모두 실행 도구는 다른 프로그램을 종료하거나, 무언가를 설치하거나, 파일을 지우지 않습니다. 원인을 해결한 뒤 같은 폴더에서 다시 실행합니다.

| 화면 메시지 | 할 일 |
|---|---|
| `node` 또는 `npm`을 찾을 수 없음 | Node.js 24.19.0을 설치하고 새 PowerShell 창에서 `node --version`과 `npm --version`을 확인합니다. |
| `npm run check` 실패 | 표시된 문법 오류와 파일 경로를 확인합니다. 이 명령은 기능 검사가 아닙니다. |
| `EADDRINUSE` 또는 포트 사용 중 | 다른 프로그램을 종료하지 않습니다. `$env:ON_PORT='5190'`을 설정한 뒤 `npm start`를 실행하고 `:5190` 주소를 엽니다. |
| `package.json`을 찾을 수 없음 | `Get-Location`과 `Test-Path .\package.json`으로 현재 위치를 확인하고 저장소 최상위로 이동합니다. |
| `바로가기(링크)로 연결된 폴더` / `ReparsePoint` | 제공 시작 도구가 해당 경로를 거부한 것입니다. 프로젝트를 옮기지 말고 저장소 최상위에서 `npm start`를 실행합니다. |
| `…초 안에 뜨지 않았습니다` | 창의 메시지 전체를 강사에게 보여 줍니다. 필요하면 5장의 도움정보도 함께 보냅니다. |

실행 도구 밖의 계정 연결·AI 승인·기록 조회 오류는 [CONNECTION_TROUBLESHOOT.md](CONNECTION_TROUBLESHOOT.md)에서 오류 코드로 찾습니다.

## 5. 도움정보 복사

강사에게 현재 상태를 보여 줄 때 씁니다. 도움정보에는 비밀값(키·토큰)이 들어가지 않으며, 자동으로 어디에도 전송되지 않습니다.

1. 「보호 현황」 화면의 **도움정보** 칸에서 「도움정보 불러오기」를 누릅니다.
2. 표시된 내용을 직접 읽어 봅니다.
3. 「확인했으며 복사합니다」를 누른 뒤 강사에게 붙여 넣어 보냅니다. 자동 복사가 안 되면 선택된 내용을 `Ctrl+C`로 복사합니다.

AI 연결 문제는 **AI 연결** 칸의 「연결 도움정보 보기」를 같은 방법으로 씁니다.

## 6. 앱 안의 AI 연결은 별도입니다

- 앱이 실행됐다는 것은 내 PC의 서버가 응답했다는 뜻입니다. AI 연결에 성공했다는 뜻은 아닙니다.
- AI 연결은 화면의 **AI 연결** 칸 안내를 따릅니다. 주소나 키를 직접 입력하지 않습니다.
- 「예제」나 「연결 없음」 상태는 실제 연결 성공이 아닙니다.
- 여기서 말하는 AI 연결은 17단계부터 앱 화면 안에서 쓰는 AI입니다. 단계 통과를 정하는 공식 판정과는 다릅니다(8장). 앱 안 AI 연결이 되지 않아도 공식 판정은 따로 진행됩니다.

## 7. 시작 틀 업데이트

제공 파일이 바뀌면 **강사·운영자가** 업데이트를 적용합니다. 학생이 직접 하지 않습니다. 운영 절차는 [STARTER_UPDATE.md](STARTER_UPDATE.md)의 「운영 도구로 업데이트하기」를 따릅니다.

- 업데이트하기 전에 내 작업을 커밋해 되돌아갈 지점을 만들어 둡니다.
- 내가 고친 파일과 `student/` 폴더의 파일은 덮어쓰지 않고 「보존」으로 남깁니다.
- 업데이트는 파일을 지우지 않습니다.
- 결과를 확인하지 못하면 성공으로 보지 않습니다. 강사가 미리보기부터 다시 확인합니다.

## 8. 제출

이번 마무리 과정은 설치 프로그램 포장을 하지 않습니다. `package.json`에 `package-app` 명령이 없으므로 `npm run package-app`을 실행하거나 새 포장 스크립트를 만들지 않습니다. 자세한 단계 제출 화면 안내는 ALEPH 방어전 상황실의 「4차 방어전」 탭에 있습니다.

1. 프로젝트 변경 사항을 확인하고 필요한 파일만 커밋한 뒤 GitHub `main`에 푸시합니다. 충돌이나 거절이 있으면 `--force`로 덮어쓰지 말고 원인을 먼저 확인합니다.
2. 푸시 후 프로젝트 폴더에서 `git rev-parse HEAD`로 나온 40자리 커밋과 GitHub `main`의 최신 커밋이 같은지 확인합니다.
3. 13~20단계는 워크벤치의 「포털 제출 준비」를 사용할 수 있습니다. 21·22단계는 ALEPH 과제 화면에 저장소 주소와 해당 단계의 40자리 커밋을 직접 입력합니다. 비공개 저장소라면 과제 화면의 「비공개 저장소 원문 준비 방법」과 `student-source-cli.mjs` 안내를 그대로 따릅니다. 비공개 저장소를 공개로 바꾸지 않습니다.
4. 저장소·커밋·단계를 확인하고 과제 화면에서 제출합니다. 원문 전달 완료와 AI 검토 통과는 서로 다른 상태입니다.

GitHub에 푸시하거나 실행 화면을 확인한 것만으로 ALEPH 제출·통과를 뜻하지 않습니다. 포털은 제출한 원문 커밋을 검토하며 학생 코드를 대신 실행하지 않습니다. 저장소 원문 검토와 실제 외부 시스템 연결·운영 인증도 구분합니다.

21·22단계에서 실행 기록은 학생 진술입니다. AI 원문 검토 결과를 새 환경에서 실행 성공한 증거, 실제 운영 인증 또는 v1.0 자동 인증으로 표현하지 않습니다.

## 9. 담당자가 SDP 연결 설정을 안내한 경우

SDP 연결 옵션이 포함된 배포본을 받고, 담당자가 본인 프로젝트에 맞는 개인 설정 파일을 안내한 경우에만 사용합니다. 인증서·개인키·토큰과 설정 파일은 학생 프로젝트, on-client 폴더, Git 저장소, 제출 ZIP 밖에 보관합니다. 설정 내용을 채팅이나 도움정보에 붙여 넣지 않습니다.

앱 폴더의 PowerShell에서 아래 명령의 설정 경로를 담당자가 안내한 실제 경로로 바꿔 실행합니다.

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -SdpHostConfig "C:\AlekovPrivate\sdp-host.json"
~~~

이 옵션은 사용자·기기 정보와 업무 앱 접근 판정에 쓰는 SDP 연결을 지정합니다. AI 연결에 쓰는 NativeHostConfig와는 별도 설정입니다. 둘 다 필요한 경우 담당자가 각각의 파일을 안내하며, 한 설정 파일을 다른 용도로 재사용하지 않습니다. SdpHostConfig를 지정하지 않으면 기본 실행 방법을 그대로 사용합니다. 예제 모드(-Demo)와 SDP 연결은 함께 사용하지 않습니다.

서버가 켜졌다는 메시지만으로 SDP 연결이나 업무 앱 접근이 승인된 것은 아닙니다. 실제 사용자·기기 정보와 선택한 앱의 판정 결과를 확인해야 합니다. 연결 오류가 나면 설정·키를 새로 복사하거나 기존 작업을 지우지 말고 담당자에게 도움정보를 전달합니다. 담당자용 설정 계약과 검증 범위는 [SDP_HOST_CONNECTION.md](SDP_HOST_CONNECTION.md)에 있습니다.
