# Sentinel Defense Battle — 처음 사용하는 사람을 위한 실행 안내

> 5일차 '따라 하기' 과제: 이 문서만 보고 다른 사람이 실행할 수 있도록 작성했습니다. 검증되지 않은 연결이나 시연 자료를 실제 보안 감지로 표현하지 않습니다.

## 0. 무엇을 실행하나요?

이 저장소는 회사 직원이 자신의 로그인/기기 상태, 업무 앱 접근 판정, 접속·보안 기록, AI 설명과 조치 제안, 패키지 취약점 조회를 확인하는 **로컬 보안 앱**입니다. 웹 브라우저의 기본 접속 주소는 `http://127.0.0.1:5189/`입니다.

**실제 연동과 예시는 다릅니다.** 기본 실행에서는 기존 보안 엔진이 연결되지 않아 일부 자료가 '연결 없음' 또는 '확인 불가'로 보일 수 있습니다. `npm run demo`는 예시 데이터를 보여 줄 뿐, 실제 회사 보안 시스템에 접속한 결과가 아닙니다.

## 1. 준비물

1. Windows PC와 PowerShell
2. Git (저장소를 복제할 때 필요)
3. Node.js **24.19.0** (저장소의 `package.json`에 선언된 검사 기준 버전)
4. 인터넷 연결 (처음 복제·도구 설치 시)

PowerShell을 새로 열고 다음을 입력해 설치 여부를 확인합니다.

```powershell
git --version
node --version
npm --version
```

`git`이나 `node` 명령을 찾지 못한다면 해당 프로그램을 설치한 뒤 **새 PowerShell 창**에서 다시 확인합니다. Node.js는 https://nodejs.org/ 에서 받을 수 있습니다. 버전이 다른 경우 실행이 되더라도 검사 환경과 동일하다고 볼 수 없습니다.

## 2. 내 PC에 받기

PowerShell에서 **프로젝트를 보관하고 싶은 상위 폴더**로 이동합니다. 아래는 사용자 문서 폴더를 이용하는 예시이며, 기존 폴더를 지우지 않습니다.

```powershell
Set-Location "$HOME\Documents"
git clone https://github.com/gyeonggumun/Sentinel-Defense-Battle.git
Set-Location .\Sentinel-Defense-Battle
git rev-parse --short HEAD
git status --short
```

이미 같은 이름의 폴더가 있다면 덮어쓰거나 삭제하지 말고 다른 상위 폴더를 선택합니다. `git rev-parse --short HEAD` 결과는 현재 받은 버전을 식별하는 값이니 기록해 두세요.

**폴더 확인:** 이 저장소는 최상위에 `package.json`, `src\server.mjs`, `student\extension.mjs`, `tools\start-alekov.ps1`이 있습니다. 별도의 `on-client` 폴더를 새로 만들거나 들어갈 필요가 없습니다. 기존 ALEPH 배포본에서만 `on-client`라는 하위 폴더 구조를 쓸 수 있습니다.

## 3. 처음 실행하기

먼저 아래 두 명령을 차례로 실행합니다.

```powershell
npm run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

- `npm run check`: 학생 화면 파일의 JavaScript 문법을 확인합니다. **기능 전체 테스트는 아닙니다.**
- 두 번째 명령: 실행 스크립트가 폴더, Node.js 버전, 포트를 점검하고 로컬 서버를 켭니다.
- PowerShell 창에서 실행 결과와 안내한 주소를 확인한 뒤 브라우저에서 **http://127.0.0.1:5189/** 를 엽니다.
- 실행 스크립트가 서버 응답을 확인했더라도 보안 엔진이나 AI 연결 성공을 뜻하지 않습니다.

앱이 정상적으로 열리면 화면에서 로그인·기기 상태, 보호 현황, 접속 기록 등의 메뉴를 살펴보세요. 연결되지 않은 데이터는 연결되지 않았다고 표시되는 것이 올바른 동작입니다.

### 예시 화면만 보고 싶은 경우

기본 서버를 먼저 `Ctrl+C`로 종료하고 다음 명령을 실행합니다.

```powershell
npm run demo
```

브라우저에서 같은 주소를 다시 엽니다. 예시 자료는 **실측 데이터가 아니며**, 과제의 실제 연결 성공 증거로 사용하지 않습니다. 데모를 끝낸 뒤 `Ctrl+C`로 종료합니다.

## 4. 따라 하기 확인 순서

아래 순서는 화면과 데이터를 혼동하지 않는 데 초점을 둡니다.

- [ ] `git rev-parse --short HEAD`로 실행 버전 기록
- [ ] `npm run check` 결과 기록
- [ ] 로컬 서버 실행 후 브라우저 접속 확인
- [ ] 메뉴를 하나씩 열고 사용자·기기·접속 결과의 출처와 상태 확인
- [ ] 연결 실패, 빈 목록, 확인 불가가 서로 다르게 보이는지 확인
- [ ] `npm run demo`를 별도로 실행해 '예시 자료' 표시 확인
- [ ] `Ctrl+C`로 서버를 종료한 뒤 다시 실행되는지 확인

**실제 Windows 상태·이벤트와 예시:** 화면에 표시되는 각 항목의 출처를 먼저 읽으세요. 로컬 PC 실측, 연동 서버 응답, 예시 자료, 확인 불가를 서로 같은 것으로 취급하지 않습니다. 조회에 실패했다면 정상이나 0건으로 바꿔 적지 않습니다.

## 5. 막혔을 때 해결하기

| 증상 | 확인 방법과 다음 행동 |
|---|---|
| `git` 또는 `node`를 찾지 못함 | Git/Node.js 설치를 확인하고 새 PowerShell 창에서 버전을 재확인합니다. |
| `tools\start-alekov.ps1`을 찾지 못함 | `Get-Location`과 `Get-ChildItem .\tools`로 현재 위치를 확인합니다. 저장소 최상위에서 다시 실행합니다. |
| 5189 포트가 이미 사용 중 | 다른 서버를 강제로 종료하지 마세요. 아래의 5190 실행 예시를 사용합니다. |
| 브라우저에 연결할 수 없음 | 서버를 실행한 PowerShell 창이 살아 있는지, 표시된 포트와 브라우저 주소가 일치하는지 확인합니다. |
| 앱은 열리지만 '연결 없음' | 기본 실행에서는 실제 SDP 엔진이 연결되지 않을 수 있습니다. 운영 담당자가 제공한 연결 설정이 있는지 확인합니다. |
| 기록이 비어 있음/확인 불가 | 빈 목록, 조회 실패, 미연결을 구별해 보고, 제공 화면의 재조회 기능으로 수동 확인합니다. |
| AI 연결·설명 실패 | AI 연결 상태와 오류 코드를 확인합니다. AI 키나 인증 토큰을 채팅·커밋·스크린샷에 붙이지 않습니다. |

포트가 충돌했다면 기존 실행을 유지하고 새 PowerShell 창에서 다음처럼 실행할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190
```

이 경우 브라우저 주소도 **http://127.0.0.1:5190/** 입니다. 포트를 바꾸었다고 실제 엔진 연결 여부가 달라지지는 않습니다.

도움말은 [실행 안내](STUDENT_LAUNCH_GUIDE.md), [연결 및 오류 해결](CONNECTION_TROUBLESHOOT.md), [실제 연결 조건](SDP_HOST_CONNECTION.md)에서 더 자세히 볼 수 있습니다.

## 6. 다른 사람에게 검증을 부탁하는 방법

문서를 처음 보는 사람에게 **추가 설명 없이** 2~5장을 순서대로 따라 하도록 요청합니다. 막히면 다음 네 가지만 남기도록 합니다.

1. 어떤 단계에서 막혔는지
2. 실행한 명령어 (비밀번호·토큰 제외)
3. 화면에 나온 오류의 첫 줄
4. 수정 후 성공/실패와 재실행 결과

작성자만 아는 폴더 경로, 이미 설치된 도구, 숨겨진 인증 설정이 필요한 단계는 안내문에 그 전제 조건을 추가해야 합니다. **이 문서는 실행 절차 안내이며, 다른 사람이 실제 실행에 성공했다는 검증 기록은 아닙니다.**

## 7. GitHub 커밋 및 ALEPH 제출 확인

실행 중인 앱과 GitHub에 올라간 파일이 같은 버전인지 확인합니다.

```powershell
git status --short
git rev-parse HEAD
git log -1 --oneline
```

`git status --short`가 비어 있으면 추적 대상 파일의 미커밋 변경이 없다는 뜻입니다. ALEPH에 제출할 때는 실제 제출하려는 **40자리 커밋 해시**를 사용하고, 제출·판정 상태는 ALEPH에서 별도로 확인합니다. GitHub 푸시나 문서 작성만으로 과제 통과가 보장되지는 않습니다.
